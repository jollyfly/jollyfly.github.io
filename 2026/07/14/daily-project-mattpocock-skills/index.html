项目描述： Matt Pocock 的 AI Agent 技能库，包含 20+ 精心设计的 SKILL.md 技能文件，帮助 Claude Code、Codex 等 AI 编码代理执行真正的工程实践，而非”Vibe Coding”。

为什么这个项目值得关注？

Matt Pocock 是 TypeScript 教育领域的知名人物（Total TypeScript 创始人，前 Vercel/Stately 工程师），拥有约 60,000 名订阅者的 newsletter。这个项目将他在日常开发中使用的 .claude 目录开源，迅速获得 16.5 万星标，成为 2026 年增长最快的 AI Agent 相关开源项目之一。

核心问题：Vibe Coding 的困境

Vibe Coding 是一种让 AI 自由发挥的编程方式，但 Matt Pocock 指出了它的致命缺陷：

  1. 缺乏工程纪律 - AI 生成的代码往往缺乏测试、文档和架构考量
  2. 上下文断层 - 开发者与 AI 对业务域的理解不一致
  3. 无法复现 - 没有记录关键决策，团队协作困难

mattpocock/skills 的解决方案是：将工程最佳实践编码为可复用的技能文件，让 AI 在执行任何任务前都遵循这些规范。

核心技能解析

1. /grill-me - 需求澄清面试技能

这是整个技能库的入口技能。AI 会不断向用户提问，直到完全理解需求。避免在需求不清时就开始”写代码”。

使用场景：

  • 项目开始前
  • 新功能规划
  • 架构设计评审

2. /tdd - 测试驱动开发

强制执行红-绿-重构循环：

  1. 先写一个必定失败的测试
  2. 用最小代码让测试通过
  3. 重构改进代码

这确保 AI 不会跳过测试或写出”凑合能用”的代码。

3. /domain-modeling - 领域建模

将业务域的术语和概念建模：

  • 确保团队（人 + AI）对术语的理解一致
  • 生成 CONTEXT.md 和 ADRs（架构决策记录）
  • 建立共享语言，避免”鸡同鸭讲”

4. /codebase-design - 代码库设计

在修改代码前，分析现有代码库：

  • 理解现有的架构模式
  • 识别需要遵守的约定
  • 规划最小的侵入式改动

5. /to-spec / /to-tickets - 流程化任务分解

将计划转化为可执行的规范和工单：

  • 产出 PRD（产品需求文档）
  • 拆分为具体的 GitHub Issue 或本地 markdown 工单
  • 为后续实现阶段提供清晰的路线图

技能分类体系

用户触发型技能（User-Invoked）

需要用户主动调用：

  • /grill-me - 需求面试
  • /ask-matt - 路由到其他技能
  • /wayfinder - 大型项目的规划导航
  • /handoff - 上下文交接

模型触发型技能（Model-Invoked）

AI 在特定场景下自动触发：

  • /tdd - 检测到实现任务时自动启用
  • /codebase-design - 修改代码前自动分析
  • /domain-modeling - 需要理解业务概念时触发
  • /code-review - 提交前自动评审

使用建议

  1. 从 /grill-me 开始 - 确保需求清晰再动手
  2. 启用 /tdd - 任何实现任务都强制测试先行
  3. 保持 CONTEXT.md 更新 - 这是团队共享记忆
  4. 善用 /handoff - 会话切换时保持上下文

总结

mattpocock/skills 不仅仅是一个提示词集合，它代表了一种将工程纪律编码为可执行技能的范式。在 AI 编程工具泛滥的当下，它提醒我们：工具会变，但工程原则永恒。

如果你正在使用或计划使用 AI 编码代理，强烈建议你花时间理解这些技能的背后的设计理念。v1.1 版本刚刚发布，引入了 wayfinder 等新技能，值得跟进。
